# 変数名や関数名などの命名に関するルールや考え方

## 全般

- 読み手の連想を裏切らない命名を意識する
  - 例えば `getUserData()` 関数が get だけでなく set しているのは悪い命名である（あるいは、そもそも関数の分割が悪いかもしれない）
  - また DB I/O を伴うなど実行時間が長いことが予測されるのであれば `getUserData()` ではなく `fetchUserData()` などにすべきである
  - このように、似た意味の英単語であっても、その選定には妥当な理由が必要である
- 名前の長さはその影響範囲、つまりスコープの広さに依存する
  - ループのインデックスや、配列の各要素を受け取るコールバックの引数など、スコープの狭い変数名は短くて構わない（例: ループの `i`、`documents` の各要素を受け取る `doc`）
  - 反対に、モジュールやコンポーネントのトップレベルに宣言されるような変数や関数、複数ファイルから参照されうるものであれば、`data`, `info`, `item` のような抽象名は避ける
- 命名が長くなりすぎる場合にのみ [comment.md](comment.md) に従ってコメントで補足する（ただし、コメントを命名の考慮をサボる言い訳に利用しない）
- 意味のある値は定数化する（マジックナンバーを避ける）

## 具体的なルール

- フラグのニュアンスを持つ boolean 変数は、is, are, has, have, can, should などの状態動詞や助動詞から始める
- DB や API から受け取る型とアプリ内部で使う型が異なる場合は、用途が伝わる名前を付けて区別する（例: `ProductResponse` と `ProductViewModel`）
- 定数は、言語の慣習に従って変数と区別できる表記にする（具体的な表記は `<言語名>.md` に従う）
  - ここでいう定数とは、再代入されない設定値・列挙値・共有される不変データを指す
