# ルールの構成

[English](../en/rules.md) | 日本語

## 概要

このドキュメントでは、dot-agents が反映するルールの構成について書いています。具体的には、以下のようなことについて書いています。

- ルールの分け方（core / lang / stack と AGENTS.md の共通部分）と、モジュールの一覧
- 取り込む側のリポジトリ（以下、対象リポジトリという。）でのファイル名
- ルールの書き方の方針と、ルールを追加・変更する手順

ただし、以下のような内容は扱っていません。

- 各ルールの本文（詳しくは、リポジトリルートの `rules/` と `agents-md/shared.md` を参照してください）
- CLI の使い方（詳しくは、[cli.md](./cli.md) を参照してください）

どのルールが反映されるかを知りたいときや、ルールを追加・変更したいときに読んでください。

## ルールの分類

dot-agents のルールは、すべての対象リポジトリに入る部分と、言語やフレームワークに応じて選ぶ部分に分かれています。

| 分類 | 置き場所 | 反映先 | 選び方 |
| --- | --- | --- | --- |
| AGENTS.md の共通部分 | `agents-md/shared.md` | `AGENTS.md` の目印で囲んだ範囲 | 常に入る |
| core | `rules/core/` | `.agents/rules/` | 常に入る |
| lang | `rules/lang/` | `.agents/rules/` | 言語ごとに選ぶ |
| stack | `rules/stack/` | `.agents/rules/` | フレームワークやライブラリごとに選ぶ |

AGENTS.md の共通部分には、作業の進め方やコードスタイルの原則など、LLM が常に意識すべき短い指示を書いています。ここから `.agents/rules/` を参照するよう指示しているので、詳しいルールは必要に応じて読まれます。

ルールの 1 ファイルを、モジュールと呼びます。現在のモジュールは以下のとおりです。

| 分類 | モジュール | 内容 |
| --- | --- | --- |
| core | comment | コメントを書く前の確認事項と、コメントに書かない情報の行き先 |
| core | documentation | ドキュメントの構成と書き方 |
| core | git | ブランチ・コミットメッセージ・PR の書き方 |
| core | naming | 変数名や関数名の付け方 |
| core | readability | 関数の責務や条件分岐など、読みやすさの原則 |
| core | review | コードレビューのコメントの書き方 |
| lang | typescript | TypeScript / JavaScript の型・関数・命名・JSDoc |
| lang | rust | Rust の命名と Rustdoc |
| stack | web | Web フロントエンドのマークアップ（semantic なマークアップ・alt 属性・ターゲットサイズ） |
| stack | tailwind | Tailwind CSS の使い方 |
| stack | lucide | Lucide のアイコンの使い方 |
| stack | vue | Vue のコンポーネントとライフサイクル |
| stack | react | React のコンポーネントとライフサイクル |
| stack | astro | Astro のコンポーネント・ライフサイクル・画像・公式ドキュメント |

最新の一覧は、`npx github:otTATto/dot-agents list` でも確認できます。

## 反映先でのファイル名

lang と stack のモジュールは、分類のフォルダを外して `.agents/rules/` の直下に置かれます。

| dot-agents での置き場所 | 対象リポジトリでの置き場所 |
| --- | --- |
| `rules/core/comment.md` | `.agents/rules/comment.md` |
| `rules/lang/typescript.md` | `.agents/rules/typescript.md` |
| `rules/stack/vue.md` | `.agents/rules/vue.md` |

そのため、モジュール名は分類をまたいで重ならないようにします。重なった場合、CLI はエラーで止まります。

対象リポジトリ自身のルールも、`.agents/rules/` に置いて構いません。dot-agents が反映するファイルと同じ名前でなければ、dot-agents はそのファイルに触れません。

## ルールの書き方の方針

ルールは、原則を core に、具体的な書き方を lang と stack に分けて書きます。どの言語のリポジトリにも core が入るので、core に特定の言語の書き方が混ざると、関係のないリポジトリでも LLM がそれに従おうとしてしまうからです。

- core には、言語やフレームワークに依存しない原則だけを書く（例:「型を明確にし、使用言語の型システムを活用する」）
- その原則の具体的な書き方は、lang や stack に書く（例: TypeScript では `any` を使わない、Vue では `onUnmounted` でリソースを解放する）
- core から具体的な書き方を任せるときは、`<言語名>.md` に従う、のように参照する
- 例に使う題材は、注文や商品のような汎用的なものにする（特定のプロジェクトのドメインに寄せない）

lang と stack のモジュールは、トピックごとの見出し（コンポーネント・ライフサイクル・命名・コメントなど）で構成し、ルールを足すときにどこへ書けばよいか分かるようにしています。

## ルールを追加・変更する手順

ルールの追加や変更は、対象リポジトリではなく、dot-agents の `rules/` と `agents-md/` で行います。対象リポジトリで直接編集すると、次の `sync` と `check` で止まります。

1. 変更したい内容を issue に立てて、方針を相談する
2. ルールを書く
   - 既存のモジュールを変更する場合は、該当するファイルを書き換える
   - モジュールを追加する場合は、`rules/<分類>/<モジュール名>.md` を作る。ファイルの先頭は `# ` で始まる見出しにする（`list` で表示される説明になる）
3. `node bin/dot-agents.mjs sync` で、dot-agents 自身にも反映する
4. モジュールを追加した場合は、このドキュメントの [## ルールの分類](#ルールの分類) に 1 行追加する
5. PR を出してマージし、タグを付けてリリースする
6. 対象リポジトリで `sync` を実行して、新しいルールを取り込む

ルールの変更は、すべての対象リポジトリでの LLM の振る舞いに影響します。そのため、変更は必ず dot-agents に集め、バージョンを付けて配る流れを守ります。
