# CLI リファレンス

[English](../en/cli.md) | 日本語

## 概要

このドキュメントでは、dot-agents の CLI の動作について書いています。具体的には、以下のようなことについて書いています。

- 各コマンド（`init` / `sync` / `check` / `list`）の使い方とオプション、コマンドが止まる条件
- 取り込む側のリポジトリ（以下、対象リポジトリという。）に反映されるファイル
- 対象リポジトリに置かれる設定ファイル `.agents/dot-agents.json` の項目

ただし、以下のような内容は扱っていません。

- 導入・更新のおおまかな手順（詳しくは、[README.ja.md](../../README.ja.md) を参照してください）
- 反映されるルールの中身と分け方（詳しくは、[rules.md](./rules.md) を参照してください）

コマンドが思いどおりに動かなかったときや、反映の仕組みを詳しく知りたいときに読んでください。

## コマンド一覧

dot-agents には 4 つのコマンドがあり、いずれも対象リポジトリのルートで実行します。

| コマンド | 何をするか | ファイルを書き込むか |
| --- | --- | --- |
| `init` | 反映するモジュールを選び、対象リポジトリに初めて反映する | 書き込む |
| `sync` | 設定ファイルの選択に従って、もう一度反映する | 書き込む |
| `check` | 反映したファイルが手元で編集・削除されていないかを確かめる | 書き込まない |
| `list` | 選べるモジュールを一覧表示する | 書き込まない |

コマンドは `npx github:otTATto/dot-agents <コマンド>` の形で実行します。以降の例では、`npx github:otTATto/dot-agents` を `dot-agents` と省略します。

いずれのコマンドも、成功すると終了コード 0、失敗したり問題が見つかったりすると終了コード 1 で終わります。

## init

`init` は、反映するモジュールを選んで、対象リポジトリに初めて反映します。モジュールの選び方は、対話式と引数指定の 2 通りがあります。

```sh
dot-agents init [--lang <names>] [--stack <names>] [--core-only] [--force]
```

| オプション | 意味 |
| --- | --- |
| `--lang <names>` | 反映する lang のモジュール名（カンマ区切り。例: `typescript,rust`） |
| `--stack <names>` | 反映する stack のモジュール名（カンマ区切り。例: `web,vue,tailwind`） |
| `--core-only` | lang と stack を選ばず、core だけを反映する（`--lang` / `--stack` とは同時に指定できない） |
| `--force` | 対象リポジトリに同じ名前のファイルがあっても上書きする |

### 対話式で選ぶ

オプションを何も付けずに端末から実行すると、lang と stack を選択肢から選べます。選んだ内容を確認してから反映し、途中で中止した場合は何も書き込みません。

選択肢には、対象リポジトリの内容から推測したモジュールに、はじめからチェックが入っています。推測の仕組みは以下のとおりです。

| モジュール | 選ばれる条件 |
| --- | --- |
| typescript | `package.json` または `tsconfig.json` がある |
| rust | リポジトリ内のどこかに `Cargo.toml` がある（`.git`・`node_modules`・`target`・`dist`・`build` の中は探さない） |
| vue / react / astro | `package.json` の依存に、同じ名前のパッケージがある |
| tailwind | 依存に `tailwindcss` または `@tailwindcss/*` がある |
| lucide | 依存に `lucide-*` または `@lucide/*` がある |
| web | 依存に vue・react・astro・next・svelte・vite のいずれかがある |

依存には `dependencies`・`devDependencies`・`peerDependencies` のすべてを含みます。

### 引数で指定する

`--lang` と `--stack`、または `--core-only` を付けると、質問せずに反映します。LLM から実行するときや、スクリプトに組み込むときはこちらを使います。

```sh
dot-agents init --lang typescript --stack web,vue,tailwind,lucide
```

端末から対話できない状態（LLM が実行しているときなど）でオプションを何も付けなかった場合は、選べるモジュール名を表示して止まります。

### init が止まる条件

以下のいずれかに当てはまると、`init` は何も書き込まずに終了コード 1 で終わります。

- すでに初期化されている（`.agents/dot-agents.json` がある）。この場合は `sync` を使います
- 存在しないモジュール名を指定した
- 対象リポジトリに、反映するファイルと同じ名前のファイルがある（`--force` で上書きできる）
- AGENTS.md の目印に問題がある（詳しくは、[AGENTS.md の扱い](#agentsmd-の扱い)を参照してください）

選んだ内容に関係なく止まる確認（すでに初期化されているかどうか）は、質問する前に行います。

## sync

`sync` は、設定ファイルに記録した選択に従って、もう一度反映します。dot-agents を新しいバージョンに更新するときに使います。

```sh
dot-agents sync [--force]
```

反映するときは、以下のように動きます。

- 選んでいるモジュールのファイルを書き出し、中身が変わったものだけを書き換える
- 選ばなくなったモジュールのファイルを削除する
- AGENTS.md は、目印で囲んだ範囲だけを書き換える

### sync が止まる条件

以下のいずれかに当てはまると、`sync` は何も書き込まずに終了コード 1 で終わります。すべてを確認してから書き込むので、途中まで書き換わった状態にはなりません。

| 条件 | `--force` を付けると |
| --- | --- |
| 設定ファイル `.agents/dot-agents.json` がない、または壊れている | 止まる（先に `init` を実行するか、設定ファイルを直す） |
| 反映したファイルや AGENTS.md の共通部分が、手元で直接編集されている | 手元の変更を捨てて上書きする |
| 対象リポジトリに、反映するファイルと同じ名前のファイルがある | 上書きする |
| AGENTS.md に目印がない、または目印が壊れている | 止まる（目印を直す） |

手元で直接編集したファイルを検出したら、その変更は dot-agents の `rules/` に取り込み、新しいバージョンとして反映するのが基本です。手元の変更が不要な場合だけ、`--force` で上書きします。

## check

`check` は、反映したファイルが手元で編集・削除されていないかを確かめます。ファイルは何も書き込みません。

```sh
dot-agents check
```

以下のいずれかが見つかると、内容を表示して終了コード 1 で終わります。

- 反映したファイルや AGENTS.md の共通部分が、手元で直接編集されている
- 反映したファイルや AGENTS.md が削除されている
- AGENTS.md の目印に問題がある

問題がなければ、`問題ありません（dot-agents v0.1.0）` のように表示します。

あわせて、dot-agents の最新のタグを `git ls-remote` で確認し、対象リポジトリに記録されたバージョンより新しいものがあれば、更新するコマンドを添えて警告します。ネットワークにつながらないなどで確認できなかった場合も、警告を表示するだけで、終了コードは変わりません。

## list

`list` は、選べるモジュールを core・lang・stack に分けて一覧表示します。

```sh
dot-agents list [--json]
```

`--json` を付けると、以下の形の JSON を出力します。LLM やスクリプトから選べるモジュールを調べるときに使います。

```json
{
  "version": "0.1.0",
  "core": [{ "id": "core/comment", "name": "comment", "title": "コメントに関するルールや考え方" }],
  "lang": [{ "id": "lang/typescript", "name": "typescript", "title": "TypeScript / JavaScript に関するルールや考え方" }],
  "stack": [{ "id": "stack/vue", "name": "vue", "title": "Vue に関するルールや考え方" }]
}
```

## 反映されるファイル

`init` と `sync` は、対象リポジトリに以下のファイルを反映します。

| ファイル | 中身 | 手元で編集してよいか |
| --- | --- | --- |
| `.agents/rules/<モジュール名>.md` | 選んだモジュールのルール本文。先頭に、同期したことを示すコメントが入る | 編集しない |
| `.agents/dot-agents.json` | 選んだモジュールと、反映したファイルのハッシュ（詳しくは、[設定ファイル](#設定ファイル)を参照してください） | 編集しない |
| `AGENTS.md` | 目印で囲んだ範囲に、すべてのリポジトリで共通の指示が入る | 目印の外側だけ編集してよい |
| `CLAUDE.md` | `@AGENTS.md` の 1 行。Claude Code に AGENTS.md を読み込ませる | 既にある場合は dot-agents は変更しない |

反映したファイルを直接編集すると、次の `sync` と `check` で検出されます。

### AGENTS.md の扱い

AGENTS.md は、以下の 2 行の目印で囲んだ範囲だけを dot-agents が管理し、その外側は一切変更しません。

```md
<!-- dot-agents:begin -->
<!-- dot-agents:end -->
```

AGENTS.md がない場合は、共通部分と「## このリポジトリについて」という見出しで新しく作ります。対象リポジトリに固有の指示は、この見出しの下など、目印の外側に書きます。

AGENTS.md がすでにあって目印がない場合は、共通部分を入れたい位置に上の 2 行を自分で挿入してから、もう一度実行します。dot-agents は差し込む位置を推測しないので、`--force` を付けても書き込みません。開始と終了の目印は、この順に 1 つずつ置きます。

### CLAUDE.md の扱い

CLAUDE.md がない場合は、`@AGENTS.md` の 1 行だけで作ります。Claude Code はこの行によって AGENTS.md を読み込みます。

CLAUDE.md がすでにある場合は、変更しません。`@AGENTS.md` の行がなければ警告を表示するので、必要に応じて自分で追加します。

## 設定ファイル

`.agents/dot-agents.json` は、対象リポジトリに反映した内容を記録するファイルです。`init` が作り、`sync` が更新し、`check` が読みます。

| 項目 | 中身 |
| --- | --- |
| `version` | 最後に反映した dot-agents のバージョン |
| `modules` | 選んだ lang と stack のモジュール ID（`lang/typescript` など。core は含まない） |
| `files` | 反映したファイルのパスをキー、中身のハッシュを値とするオブジェクト |
| `blocks` | AGENTS.md の目印で囲んだ範囲のハッシュ |

パスは、OS によらず同じ設定ファイルになるよう、対象リポジトリのルートからの相対パスを `/` 区切りで書きます。ハッシュは改行コードを LF に揃えてから計算するので、Windows で改行コードが CRLF に変わっても、編集とはみなしません。

選ぶモジュールを変えたいときは、`modules` を書き換えてから `sync` を実行します。それ以外の項目は dot-agents が管理するので、手で書き換えないでください。
